# M5 Acceptance Matrix

This matrix distinguishes inherited foundation from M5 behavior. `not_started` does not assert absence of every supporting primitive; it means M5 acceptance has not been demonstrated. Update each row with exact source, test command and outcome after implementation.

### Packet H cover reconciliation continuation (2026-10-28)

Captured redemption and exact reversal now post balanced journals through durable outbox events into `event_cover_venue_payable_held`, a separate account excluded from payout totals. Reversal requires the server-side M5 accounting approval flag, Finance/Ops/Admin/Super Admin authority, matching ticket/account/capture provenance and a reason; retries are idempotent. Admin reconciliation continues to report settlement as held/ineligible. The Firestore concurrent reversal test is present but skipped when the emulator is unavailable. Packet H remains in progress: provider refund/reversal posting, event-level reconciliation, approved settlement policy and connected acceptance remain open.

Read-only per-account reconciliation now derives net redemption after valid reversals and validates refunds against issuance, then checks reserved, redeemed, refunded and remaining totals against the materialized account. Admin's ticket-scoped inspection now shows ledger-computed refunds beside the stored account amount; it remains read-only and explicitly does not imply payout availability. Core event-cover and Admin-ops tests passed 17, Admin ticket API tests passed 9, Admin UI tests passed 4, affected typechecks passed, and contract parity passed 239. Refund/reversal writers, expiry, event-level reconciliation, canonical finance journals and settlement holds remain incomplete; Packet H stays in progress.

### Packet C eligibility continuation (2026-10-28)

Checkout quote, inventory hold creation, and free RSVP now require a line-level attestation for restricted audience (male, female, couple, student, member) and age-bounded tiers. Partner tier editing can configure Student and Member options and explains that the Guest attests at checkout while the Venue may verify at entry. Guest review shows the policy and records one acknowledgement for all attendees on each selected line. Holds and paid/free order lines snapshot the policy, acknowledgement, and timestamp without collecting gender or date of birth. Backend quote/hold and RSVP enforcement is authoritative; legacy orders remain readable. Focused Core checkout tests passed 16, API checkout/RSVP/public-tier tests passed 26, Guest checkout/mapping tests passed 37, Partner ticket editor tests passed 3, affected typechecks passed, and contract parity passed 239 checks. Venue verification workflow, student/member evidence support, and connected acceptance remain incomplete; Packet C stays in progress.
