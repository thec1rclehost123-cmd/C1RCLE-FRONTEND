### Interface 2 — venue/host overview — ✅ backend `802334c`, frontend `593351e`

`/partner/[studio]/overview` for `venue` and `host` now reads five endpoints
server-side. New: `src/lib/overview/{api-overview-repository,overview-view-model,load-overview-data}.ts`
(+ tests) and `OverviewLoadFailureState.tsx`, mirroring the finance path's
three-layer shape.

Four backend routes were needed (see `FRONTEND-GATEWAY-BACKEND-MAP.md` §4.5):

| route                  | why it was missing                                       |
| ---------------------- | -------------------------------------------------------- |
| `…/finance/orders`     | the finance desk's "where did this balance come from"    |
| `…/analytics/trends`   | a dashboard's core series                                |
| `…/analytics/calendar` | the month grid, incl. server-computed `firstDayOffset`   |
| `…/analytics/events`   | event cards need `ticketsSold` + `capacity` + venue name |

`trends` is granularity-parameterised rather than one range at three zooms —
`OverviewTrendCard` switches metric _and_ range client-side off a single
`series` array, so the four ranges are four different shapes (1D wants hours,
1W/1M want days, All wants months). The loader therefore issues three
concurrent trend reads; the 30-day daily read serves both 1W and 1M.

**Three backend facts forced honesty changes rather than field-filling** — each
looked trivial in the fixture, and each would have put a fabricated number on a
partner's dashboard:

- **No doors time exists.** An event is `startAt`/`endAt` and nothing else.
  `doorsLabel` became optional and is absent on the API path. Inferring one
  would print a time no partner ever set.
- **No org-level `clicks`.** Referral-link clicks are a per-promoter vanity
  counter with no authoritative attribution, so `trends` carries two metrics
  even though the card's switcher offers three. (Promoter overview keeps
  clicks — per-link, where it is meaningful.)
- **No counterparty names.** The partnership DTO carries ids, and no
  partner-side endpoint resolves an org the viewer is not a member of, so the
  network card shows a shortened id.

`OverviewEvent.capacity` widened to `number | null`: the card divides by it, and
a venue that never declared a capacity is not a venue with capacity zero.

Two real view-model bugs were caught by the new tests: the calendar heading
followed the _render_ month rather than the calendar's, and `value` summed the
plotted sub-sample (understating 1W by three quarters, since 7 points are
drawn from a 30-bucket read).
