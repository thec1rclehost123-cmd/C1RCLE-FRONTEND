## Observed foundations and gaps

- Backend owns canonical `TicketTier`, `Order`, `Entitlement`, scanner, refund, checkout, and generic cover-wallet models/services. M5 now includes per-person group entitlements and ownership/version primitives; guest claim/transfer workflows remain incomplete.
- Entitlements now distinguish purchaser and holder, persist credential version, and support transactional transfer lifecycle and versioned admission credentials. Private access grants and hidden tiers are implemented, while delivery, some privacy surfaces, and connected acceptance remain open.
- Event visibility supports public/unlisted/code/invited modes. A separate `addressDisclosure` policy now defaults private events to hidden and can reveal full address only after an event grant; new private transitions revoke managed same-organization poster ACLs and clear the event image; partner analytics also redact legacy private poster URLs. New public poster objects now have a signed 60-second cache lifetime; private transitions set `private, no-store`. All current Admin CSV routes were inspected and set `private, no-store`. Historical ACL inventory/revocation, legacy-cache invalidation and connected acceptance remain incomplete.
- A dedicated scanner credential and scan-ledger path already exists. Reuse it for rotated ownership credentials; do not put bearer data in entitlement records or add a parallel QR format.
- Existing cover wallets are event/user/organization scoped, generic balances with a separate rotating-wallet QR. They are not linked to a ticket entitlement and their scanner charge path is based on preset items. M5's per-entitlement cover requires a separate explicit linkage/authorization design; existing generic wallet behavior must not be rebranded as M5 cover.
- Existing Guest checkout, payment recovery, ticket wallet and ticket QR routes provide integration points. Partner event/tier builders, Guest event detail/wallet, Admin ticket/order controls and scanner routes require state-by-state inventory before UI work.

## First implementation boundary

Packet A added backward-compatible entitlement ownership, unit-kind and credential-version fields; legacy records remain readable and existing QR generation is preserved. Per-person group ticket issuance, access grants, paid-unit quota and ownership transfer have focused/emulator evidence. Packet E uses version-specific keys and checks the expected credential version inside atomic online admission. Transfer writes require offline-manifest disable and post-drain attestation; the separately audited freeze-release recovery route preserves the frozen transfer history. Packet F/G has only domain primitives, not an end-to-end cover workflow. M5 runtime gates remain closed and connected Test Mode acceptance is blocked until the already-authorized local runtime/configuration is verifiably available.
