# M5 Domain and Policy Decisions

These are implementation defaults, not legal, tax, accounting or merchant approval. Record any change with an explicit version. No default below authorizes live activation.

| Decision         | Conservative implementation default                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Approval / activation gate                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Ticket ownership | Keep purchaser, current holder, pending recipient and original refund destination distinct. Legacy entitlements default to purchaser as holder only where the stored user identity is present; otherwise preserve unknown/read-only.                                                                                                                                                                                                                                                                                  | Existing records are never silently transferred.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Group units      | One admission entitlement per attendee unit; a group bundle stores member count and each member's eligibility/claim separately.                                                                                                                                                                                                                                                                                                                                                                                       | Historical couple entitlements remain their original multi-admit shape.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Credential       | Reuse the existing short-lived signed QR path; bind entitlement, event, issuer/key version, credential version, validity and current status; rotate on ownership change.                                                                                                                                                                                                                                                                                                                                              | Transfer requires offline manifests disabled and an operator attestation that 12-hour manifest validity plus 24-hour sync grace have elapsed. Runtime flag wiring remains unavailable; no transfer activation is authorized by this guard alone.                                                                                                                                                                                                                                                                                                 |
| Access           | Public/unlisted/code-gated/identity-invited are separate modes. `unlisted` is direct-link access, excluded from discovery, and explicitly not confidential. Hash access-code verifiers; separate access, discount and M4 attribution codes. Grants are bounded and revocable. Ticket `accessMode` supports public/code/invited; code tier reads, quote and hold require a current user-bound grant. Event `addressDisclosure` is independently `public`, `after_grant` or `hidden`; private events default to hidden. | Private event detail/tier and address behavior has API/UI/emulator-style automated coverage, but prior public media revocation, all export/cache surfaces, secure artwork delivery and connected acceptance remain incomplete. Private access activation stays off until the full surface review passes. Partner analytics event cards now redact legacy poster URLs for code/invited events; this does not change bucket ACL state or retract previously copied URLs.                                                                           |
| Eligibility      | Collect only an explicit minimum attestation; never infer from name/photo/ID. Enforce per holder for groups.                                                                                                                                                                                                                                                                                                                                                                                                          | Policy/legal approval required before affected tier activation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Limits           | One active free RSVP per account with persisted Better Auth `emailVerified` per event; ten active paid units per purchaser/event across orders and tiers, including active holds. Transfers do not reset purchaser history. Group-shaped free RSVP tiers are rejected until all attendee claims are identity-bound.                                                                                                                                                                                                   | Email verification is account identity, not proof of one human; document multi-account limits.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Transfer         | Sender remains current holder while pending. Accept atomically changes holder and credential version; one pending transfer; no transfer after check-in, refund lock, freeze, chargeback, cover use or pending cover authorization. Free RSVP entitlements cannot transfer.                                                                                                                                                                                                                                            | No paid resale; support recovery requires explicit audit. Transfer remains disabled until verified-contact invitation delivery and offline drain requirements are met.                                                                                                                                                                                                                                                                                                                                                                           |
| Cover            | Event-specific, nonwithdrawable INR obligation linked to one entitlement; never a general wallet. Host proposals snapshot venue/merchant, amount, minimum spend, windows, categories, alcohol rule, partial/split tender, refund/transfer terms, commission basis and gated unused-balance policy. Venue acceptance binds the exact proposal ID, version and terms digest. ₹500 admission + ₹1,500 cover at 15% admission-only commission yields ₹75 before admission discount, excluding cover/fees/tax.             | Cover now connects to checkout/Firestore, Guest wallet and Venue guest-confirmed redemption, with separate collection liability posting and transactional issuance/reserve/redeem/refund outbox facts. Canonical redemption payable, provider refund/reversal journal, full per-event reconciliation and held-settlement read models remain incomplete. Venue/merchant, legal, tax and accounting approvals are absent; activation stays disabled. Unused-cover expiry, tax, voucher treatment, account mapping and settlement require approval. |
| Redemption       | Online preauthorization reserve/confirm/capture/void with a short expiry, terminal/Venue/event binding, guest challenge and replay-safe operation ID. A pending Guest request reserves funds; Guest confirmation captures that exact reservation, expiry voids it, and transfer/refund transactions conflict with active reservations. Split tender is clearly external to C1RCLE.                                                                                                                                    | Emulator evidence covers concurrent consumption, expiry/release, refund-freeze conflicts, transfer conflicts and replay-safe ledger/outbox writes. Connected acceptance and canonical Venue payable posting remain incomplete, so real redemption stays disabled.                                                                                                                                                                                                                                                                                |
| Refunds          | Freeze admission/cover while provider outcome is unresolved. Never refund consumed cover automatically. Refund to original payment path and reverse only actually refundable admission commission.                                                                                                                                                                                                                                                                                                                    | Interrupted event/chargeback/used cover goes to reviewed, audited resolution.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Waitlist         | Deterministic FIFO offer order, one active entry per verified person/tier scope, bounded hold, no automatic charge.                                                                                                                                                                                                                                                                                                                                                                                                   | No offer if eligibility/private access fails at offer time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Event policy     | Snapshot terms at sale; material changes create a version and cannot reduce sold rights silently. Use event timezone for cutoff/redemption windows.                                                                                                                                                                                                                                                                                                                                                                   | Cancellation/reschedule remedy wording requires policy approval.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Finance          | Extend canonical journal/reserve source of truth; hold Venue payable until reconciliation/approval. Never execute payout in M5.                                                                                                                                                                                                                                                                                                                                                                                       | Chart-of-accounts and release semantics require finance approval.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

M4 remains a dependency: its unapproved Promoter agreement and missing connected test roles still block those acceptance scenarios. Preserve M4 attribution snapshots and do not retroactively change historical commissions.
